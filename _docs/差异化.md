1️⃣ 顶部：今日一句话解释（Narrative Header）
--------------------------------

### 这是 Chronote 的“脸”

**位置**：页面最顶部  
**形式**：一张卡片 / 一段自然语言

### 示例（不是文案，是结构）

### 产品设计要点

*   只说 **1–2 个判断**

2️⃣ 时间结构总览（Structure Overview）

📌 **这是“从一句话 → 证据”的第一步**

*   时间段（10:32–11:18）

*   被 Chronote 归类的原因（简要）
    

📌 **这是用户“信你”的关键层**

很好，这一步**完全是架构师该做的事**。

你可以把下面内容理解为一份 **《Chronote 时间解释引擎 · 算法设计说明书（概念版）》**。

* * *

一、总原则（架构师先立规矩）
==============

在给任何算法之前，Chronote 必须明确 4 条**不可违反的设计原则**：

1.  **单向推导**
    
    *   上层结论不能反推、修改下层数据
        
2.  **可回溯**
    
    *   任一高层结论，都能指回底层 activity
        
3.  **确定性优先**
    
    *   同一输入 → 同一输出（不追求“聪明”）
        
4.  **解释优先于精度**
    
    *   宁可“少解释一点”，也不要“解释得像魔法”
        

* * *

二、L0 → L1：Raw Activity → Session / Episode
==========================================

### 🎯 目标

把**碎片化的 app start/end**，合并成**连续上下文片段**。

* * *

核心算法思想：连续性分段（Continuity Segmentation）
-------------------------------------

### 输入

*   按时间排序的 activity 流：
    
        (app, start, end)
        
    

* * *

### 关键判定变量（架构级）

1.  **时间间隔阈值（Idle Gap）**
    
    *   若相邻 activity 间隔 > T（如 2–5 分钟）  
        → 强制切断 session
        
2.  **前后台连续性**
    
    *   连续 foreground 活动优先合并
        
    *   background 只作为附属，不主导 session
        
3.  **主题一致性（弱）**
    
    *   app 类型相近（编辑器 + 浏览器）
        
    *   不做语义判断，只做“相似性”
        

* * *

### 输出

*   Session：
    
    *   start / end
        
    *   包含的 activity 列表
        

📌 **Session 只是“时间连续性”的抽象，不带任何行为判断**

* * *

三、L1 → L2：Session → Behavioral Block（关键）
========================================

这是 Chronote **第一个“有认知”的算法层**。

* * *

核心算法思想：行为主导性 + 切换密度
-------------------

### 🎯 抽象目标

把一个 session 解释为：

> **“人类在干的一件事”**

* * *

Behavioral Block 的 4 个核心指标（必须）
------------------------------

架构师要明确这 4 个“计算维度”，实现者按此算即可。

* * *

### 1️⃣ 主导行为（Dominant Activity）

**定义：**

*   占用时间最长 / 出现最集中的 app 或 app 集合
    

**用途：**

*   给 Block 一个“行为锚点”
    
*   不用于评价
    

* * *

### 2️⃣ 行为切换密度（Switch Density）

**定义：**

    切换次数 / Block 总时长
    

**用途：**

*   判断行为是否稳定
    
*   后续结构分类的关键输入
    

* * *

### 3️⃣ 连续时长（Continuity Length）

**定义：**

*   Block 的总持续时间
    
*   重点关注是否超过某些阈值（如 30min / 45min）
    

* * *

### 4️⃣ 行为复杂度（Activity Entropy）

**概念级定义：**

*   app 分布是否集中，还是高度分散
    

（架构层不关心怎么算，只关心“高 / 中 / 低”）

* * *

### 输出

*   Behavioral Block：
    
    *   start / end
        
    *   dominant activity
        
    *   switch density
        
    *   duration
        
    *   complexity
        
    *   引用 session / activity
        

📌 **这一层是 Chronote 的“原子语义层”，一定要稳定**

* * *

四、L2 → L3：Behavioral Block → Time Structure（核心）
===============================================

这是 Chronote 和竞品**真正分叉的地方**。

* * *

核心算法思想：规则驱动的结构映射（Rule-based Mapping）
------------------------------------

> ⚠️ 架构师必须明确：  
> **Time Structure 是“解释视角”，不是事实**

* * *

输入
--

*   Behavioral Block 指标集合
    

* * *

结构分类的判定逻辑（概念级）
--------------

架构师需要定义一张**规则矩阵**，例如：

### 示例（不是参数，是结构）

#### 🧱 Deep Block

*   duration：长
    
*   switch density：低
    
*   complexity：低–中
    

* * *

#### 🧩 Fragmented Block

*   duration：中等或短
    
*   switch density：高
    
*   complexity：高
    

* * *

#### 📥 Passive Consumption

*   dominant activity：浏览 / 视频 / 阅读
    
*   switch density：低
    
*   complexity：低
    

* * *

#### 🔄 Context Switching

*   switch density：极高
    
*   dominant activity：不稳定
    

* * *

### 输出

*   每个 Block → 一个 Structure Label
    
*   同时聚合出：
    
    *   当日结构分布
        

📌 **规则必须可读、可调、可解释**

* * *

五、L3 → L4：Time Structure → Patterns（跨日）
=======================================

* * *

核心算法思想：时间窗口 + 结构相似性
-------------------

### 🎯 抽象目标

发现：

> **“你在重复什么样的时间结构”**

* * *

Pattern 识别的 3 个维度
-----------------

### 1️⃣ 时间位置

*   上午 / 下午 / 晚上
    
*   固定时间窗口（如 9–11）
    

* * *

### 2️⃣ 结构特征

*   Deep / Fragmented 占比
    
*   切换密度趋势
    

* * *

### 3️⃣ 重复频率

*   N 天中出现 ≥ K 次
    

* * *

### 输出

*   Pattern 对象：
    
    *   描述
        
    *   时间范围
        
    *   出现频率
        
    *   支撑的 Block 引用
        

📌 **Pattern 是统计描述，不是预测**

* * *

六、L4 → L5：Narrative（解释生成）
=========================

* * *

核心算法思想：模板化语言压缩（Template-based Summarization）
--------------------------------------------

> ⚠️ 架构师一定要禁止“自由生成”

* * *

输入
--

*   Today 的 Time Structure
    
*   最近 Pattern
    
*   对比基准（昨日 / 上周）
    

* * *

Narrative 生成的规则（概念）
-------------------

### 1️⃣ 只选 1–3 个最显著事实

*   占比最高
    
*   变化最大
    
*   重复最明显
    

* * *

### 2️⃣ 每条解释必须能回答：

*   **是什么**
    
*   **在哪里**
    
*   **持续多久**
    

* * *

### 3️⃣ 每条 Narrative 必须绑定：

*   对应的 Block / Pattern ID
    

📌 **语言是结果，不是判断来源**

* * *

七、给实现者的一句话总结（非常重要）
==================

> **Chronote 的算法不是“预测用户”，  
> 而是“忠实地描述用户已经发生的行为结构”。**

=========================

如果你真要交给实现者，我建议你输出这 3 份文档：

Chronote Time Interpretation Spec v0.1
======================================

版本信息
----

*   Version: v0.1
    
*   Date: 2026-01-22
    
*   Author: Chronote Product & Architecture Team
    
*   Purpose: 定义 Chronote 的时间解释引擎核心算法和抽象规范
    

* * *

1\. 概述
------

Chronote 的时间解释引擎将用户一天的 Mac 活动数据，转化为**多层抽象解释**，帮助用户理解**时间是如何被花费的**。  
核心原则：

1.  **单向依赖**：高层抽象不影响低层数据
    
2.  **可回溯**：每个结论可追溯至原始 activity
    
3.  **确定性优先**：同一输入产生同一输出
    
4.  **解释优先于精度**：宁可少解释，也不制造黑箱
    

* * *

2\. 数据层级与抽象
-----------

### 2.1 L0 · Raw Activity Layer

*   **定义**：不可修改的事实层
    
*   **输入**：系统记录的每个 App 活动
    
*   **数据结构**：
    

    Activity {
      id: string
      app_name: string
      start_time: datetime
      end_time: datetime
      window_title?: string
    }
    

*   **规则**：
    
    *   原始数据不做聚合
        
    *   所有高层输出都必须指向对应 activity
        

* * *

### 2.2 L1 · Session / Segment Layer

*   **定义**：按连续性聚合 activity 的时间片段
    
*   **目的**：把碎片化 activity 合并为有意义的连续行为段
    
*   **数据结构**：
    

    Segment {
      id: string
      start_time: datetime
      end_time: datetime
      primary_app: string
      activities: [Activity]
      switch_count: int
      duration: float
    }
    

*   **核心算法**：
    

1.  按 start\_time 排序 activity
    
2.  聚合规则：
    
    *   相邻 activity 间隔 <= IDLE\_THRESHOLD (默认 120s) → 合并
        
    *   切换频繁但集中在有限几个 app → 继续合并
        
    *   间隔 > IDLE\_THRESHOLD → 分割成新 Segment
        
3.  记录 segment 内切换次数、总时长、主 app
    

*   **输出**：Segment 列表
    

* * *

### 2.3 L2 · Behavioral Block Layer

*   **定义**：从 Segment 抽象为**人类可理解的行为**
    
*   **目的**：把连续活动映射为语义行为段
    
*   **数据结构**：
    

    BehaviorBlock {
      id: string
      segment_ids: [string]
      behavior_type: Enum('Deep', 'Fragmented', 'Passive', 'Communication', 'Idle')
      start_time: datetime
      end_time: datetime
      duration: float
      switch_density: float
      dominant_app: string
      complexity: Enum('Low', 'Medium', 'High')
    }
    

*   **核心算法**（规则引擎）：
    

1.  **计算指标**：
    
    *   duration = sum(segment.duration)
        
    *   switch\_density = total\_switch\_count / duration
        
    *   dominant\_app = 占用时间最长的 app
        
    *   complexity = activity entropy（高/中/低）
        
2.  **行为类型判定**：
    

| 类型 | 判定条件（示例） |
| --- | --- |
| Deep | duration ≥ 40min, switch\_density ≤ 0.05, dominant\_app\_ratio ≥ 0.7 |
| Fragmented | duration < 40min 或 switch\_density > 0.15, complexity = High |
| Passive | dominant\_app 属于阅读/视频/浏览类, switch\_density ≤ 0.05 |
| Communication | app 中有 Slack/Email/Chat, duration ≥ 5min |
| Idle | duration < 5min 或系统无 foreground activity |

*   **输出**：BehaviorBlock 列表
    

* * *

### 2.4 L3 · Time Structure Layer

*   **定义**：按行为类型聚合，展示**一天的时间结构**
    
*   **目的**：帮助用户看到时间的整体分布
    
*   **数据结构**：
    

    TimeStructure {
      date: Date
      structure_distribution: Map<BehaviorType, float>  // 占比
      deep_blocks: [BehaviorBlock]
      fragmented_blocks: [BehaviorBlock]
      passive_blocks: [BehaviorBlock]
      communication_blocks: [BehaviorBlock]
      idle_blocks: [BehaviorBlock]
    }
    

*   **核心算法**：
    

1.  将 BehaviorBlock 按类型分类
    
2.  统计每类占比（duration / total\_day\_duration）
    
3.  计算集中时段、平均块长度、最大块长度
    
4.  可生成“今日结构概览”
    

* * *

### 2.5 L4 · Patterns Layer

*   **定义**：跨日行为结构模式
    
*   **目的**：发现重复时间使用模式
    
*   **数据结构**：
    

    Pattern {
      id: string
      name: string
      time_window: TimeRange
      behavior_distribution: Map<BehaviorType, float>
      frequency: int
      supporting_blocks: [BehaviorBlock]
    }
    

*   **核心算法**：
    

1.  按天对 TimeStructure 做特征向量化
    
2.  用时间窗口 + 行为占比匹配相似性
    
3.  频率超过阈值 → 形成 Pattern
    

* * *

### 2.6 L5 · Narrative Layer

*   **定义**：自然语言解释
    
*   **目的**：让用户快速理解时间使用
    
*   **数据结构**：
    

    Narrative {
      headline: string
      supporting_facts: [string]  // 可回溯到 block 或 pattern
      tone: Enum('Analytical', 'Neutral')
    }
    

*   **核心算法**（模板化）：
    

1.  选择显著行为 / 结构特征：
    
    *   占比最高
        
    *   深度块最少/碎片最多
        
2.  根据规则生成 headline：
    
    *   例如：“今天你的时间主要被碎片化行为消耗”
        
3.  每条 narrative 绑定 supporting\_facts
    

* * *

3\. 参数说明（可调）
------------

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| IDLE\_THRESHOLD | 120s | activity 间隔超过此阈值 → 新 Segment |
| DEEP\_DURATION\_MIN | 40min | 判定 Deep 行为块最小持续时间 |
| SWITCH\_DENSITY\_HIGH | 0.15 | 切换密度高阈值，用于判定 Fragmented |
| DOMINANT\_APP\_RATIO | 0.7 | 判定 Deep 行为块主导 app 占比 |
| COMPLEXITY\_ENTROPY\_THRESH | 自定义 | 行为复杂度划分 |
